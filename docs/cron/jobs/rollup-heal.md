# Background Job Specification: `rollup_heal_{service_id}`

## 1. Overview & Objectives
- **Job Identifier:** `rollup_heal_{service_id}`
- **Category:** Rollup Self-Healing & Top-N Completeness
- **Purpose:** Idempotently scans the previous 24-48 hours to discover and backfill missing closed-hour Top-N rollup bundles.
- **Why It Runs:** Fastly log delivery has variable latency (typically 1-3 minutes). Bursty services or delayed log files can result in an hour closing before all its data lands in the buffer. Without hourly self-healing, closed hours whose last logs arrived late would be permanently omitted from precomputed Top-N rollups, forcing the dashboard to return incomplete data or fall back to slow raw scans until the daily 02:00 UTC compaction.

---

## 2. Scheduling & Cadence
- **Trigger Type:** Cron trigger (`cron`)
- **Default Schedule:** Hourly at 5 minutes past the hour (`minute=5`, e.g. 01:05, 02:05 UTC).
- **Startup Trigger:** Also scheduled with `next_run_time = NOW() + 30s` at scheduler boot.
- **Jitter & Misfire Policy:**
  - `max_instances=1`, `coalesce=True`, `misfire_grace_time=900s`.

## 5. Execution Lifecycle & Step-by-Step Logic
1. **Window Identification:** Establishes lookback window (default: previous 24 hours from current time).
2. **Missing Bundle Detection:** Calls `find_missing_hour_bundles(service_id, lookback_hours=24)`. Identifies any closed UTC hours that lack a completed bundle in `rollups/{service_id}/hour_bundles/`.
3. **Idempotent Bundle Computation:** For each missing hour:
   - Queries raw/committed log data bounded strictly by `timestamp >= hour_start AND timestamp < hour_end`.
   - Computes dimensional Top-N metrics: URLs, status codes, PoPs, ASNs, User-Agents, TLS versions, origins, and verified bots.
   - Writes consolidated `hour_bundle_YYYY-MM-DD_HH.parquet`.
4. **Validation & Atomic Publish:** Verifies file size and row counts; atomically moves into live rollup directory.
5. **Log & Telemetry:** Records execution summary in `cron_runs` (`healed_hours_count`, `duration_s`).

## 6. Telemetry, Timing & Query Audit Contract
- **100% Query & Resource Capture:**
  - **Local-Only Safety:** No outbound S3 calls to FOS; reads from local cache or DuckLake view.
  - **DuckDB Operations:** All aggregation queries are tracked via `telemetry_queries`.
  - **Budget:** Single-hour bundle generation must complete in < 1.5s on standard datasets.
- **Audit Checklist:**
  - Verify lookback window is bounded to 24 hours to prevent runaway backfills.
  - Confirm bundle generation does not double-count events across hour boundaries.
  - Confirm zero Class A FOS PUTs generated by this job.

---

## 7. Failure Modes & Recovery Runbooks
- **Missing Raw Data:** If an hour has zero log rows, an empty marker bundle is written to prevent endless re-computation attempts.
- **Corrupted Existing Bundle:** Checksums and header validation detect truncated parquet files and trigger a rebuild.
